# Agent 看到的 Markdown

[English](../en/markdown.md) · [文档目录](README.md)

页面在服务器里存成结构化的文档（和网页编辑器同一份），Agent 读写时用 Markdown。服务器的转换保证来回不走样：
读出来原样写回去，什么都不变。

## read_page 的样子

```
# 季度计划
page_id: 01JD… · 更新于 2026-11-18 13:05 UTC · 共 3 块
base: …

⟦b7Kq2⟧
## 目标

⟦Xp0aZ⟧
- 搜索 p95 小于 5ms
- 页面历史

⟦mN3rT⟧
| 名字 | 状态 |
| --- | --- |
| 搜索 | 进行中 |

没解决的评论（1 串，详细用 list_comments）：
…
```

- `⟦…⟧` 是**块编号**，只有顶层块有（一个列表、一个表格、一段代码都是一块）。改的时候用它指定块，它本身不是正文。
- `base` 是读到的版本。`edit_page` / `rewrite_page` 带回来，服务器在那个版本上改再合并：你读完以后别人新打的字不会被覆盖。
- 页面很长时分段读，末尾告诉你下一段从哪块开始（`from_block`）。
- 改列表、表格里的一项：把整块的新 Markdown 给出来，服务器会沿用没变的项。

## 支持的写法

| 内容 | Markdown |
| --- | --- |
| 标题 | `#` 到 `######` |
| 粗体、斜体、删除线、行内代码 | `**粗**`、`*斜*`、`~~删~~`、`` `代码` `` |
| 下划线、高亮 | `<u>下划线</u>`、`==高亮==`（`<mark>` 也认） |
| 链接 | `[文字](https://…)`；正文里裸露的网址也是链接 |
| 行内提及（链接小卡片） | `<https://…>` |
| 链接卡片 / 视频 / 内嵌的库 | 网址**单独一行**：`https://www.youtube.com/watch?v=…`。指向本站数据库的（`https://docs.example.com/p/<库 id>`）显示成内嵌的表格 |
| 图片 | `![说明](地址 "标题")`；只有图片的一段是图片块 |
| 列表、有序列表、待办 | `- 项`、`1. 项`、`- [ ] 待办` / `- [x] 做完了`；缩进两格是下一层 |
| 引用 | `> …` |
| 提示框 | `> [!NOTE]`、`> [!TIP]`、`> [!IMPORTANT]`、`> [!WARNING]`、`> [!CAUTION]`，后面可以跟标题：`> [!WARNING] 注意` |
| 折叠块 | `<details><summary>标题</summary>` 空一行，内容，空一行，`</details>` |
| 代码块 | ```` ```python ```` … ```` ``` ```` |
| 公式 | 行内 `$a^2+b^2$`；整块 `$$` 换行 公式 换行 `$$` |
| 表格 | GFM 表格，第一行是表头；不能合并单元格 |
| 分割线 | `---` |
| 换行 | 段落里的单个换行就是换行（不用行末两个空格） |
| 空段落 | 单独一行 `<br>` |

不认的 HTML 当文字留着，不渲染。图片宽度、图注、代码块自动换行、链接卡片显示成书签这些**只影响显示**的设置
Markdown 里没有；Agent 改写一块时，编号沿用下来的块保留原来的这些设置。

上传的文件用 `upload_file`，它返回能直接放进正文的 Markdown（图片是 `![…](/api/v1/files/…)`，别的文件是链接）。

## 评论

评论正文也是 Markdown。@ 人或 Agent：`@名字`，或者 `@[名字](user:<id>)` / `@[名字](agent:<id>)`。

## 数据库

- 每一行也是一个页面：行的正文用 `read_page` / `edit_page`（`page_id` 就是行 id），`read_page` 读行时先列出属性。
- `db_query` 返回 Markdown 表格，值是名字（选项名、人名、关联的行的名称），每行带 `row_id`。
- `db_add` / `db_update` 里属性和值都写名字：`{"状态": "进行中", "截止": "2026-11-20", "完成": "是", "负责人": "小王"}`。
  单选、多选里没有的选项会新加上。日期可以带时间 `2026-11-15T09:30`；`null` 清空。
